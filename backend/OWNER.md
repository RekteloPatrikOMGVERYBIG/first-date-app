# Запрошення та кабінет

1. Запусти PostgreSQL і backend (`postgres.ps1 start`), потім Vite.
2. Відкрий `/owner` на адресі Vite, наприклад http://localhost:5173/owner.
3. Пароль автоматично створюється під час запуску backend у
   `backend/data/owner-password.txt`. Відкрий файл у редакторі й скопіюй пароль
   у форму входу. Не надсилай його іншим і не додавай до Git.
4. Введи назву запрошення та натисни «Створити запрошення».
5. Скопіюй посилання з поля. Після відкриття гостею статус стане «Відкрито»,
   після надсилання — «Заповнено». У кабінеті натискай «Оновити» для нових даних.
6. Відповіді показуються нижче у розкривних картках, включно зі старими записами.

Посилання використовує поточну адресу браузера. `localhost` працює лише на твоєму
комп'ютері. Для телефона в одній Wi-Fi мережі відкрий кабінет через Network-адресу
Vite і копіюй посилання звідти. Для доступу через інтернет потрібне розгортання.

Головна `/` — попередній перегляд анкети; гість надсилає відповіді через `/invite/TOKEN`.
Публічна частина ніколи не повертає надіслані відповіді: повторне відкриття
заповненого запрошення показує лише повідомлення про завершення.

## Збереження та захист

Нові таблиці `invitations` і `owner_sessions` створюються без зміни старої таблиці
`responses`. `invitations.response_id` — унікальний зовнішній ключ до відповіді.
Збереження відповіді та закриття запрошення відбуваються однією транзакцією.

Сесія триває 8 годин; cookie має HttpOnly та SameSite=Strict. У базі зберігається
лише SHA-256 випадкового токена сесії. Вихід видаляє серверну сесію. Запити, які
змінюють дані власника, вимагають спеціального заголовка; CORS не увімкнено.
Пароль — випадковий секрет, який залишається у приватному локальному файлі.

Ліміт входу — 5 спроб за хвилину на адресу в пам'яті одного процесу. Для production
потрібні HTTPS, `COOKIE_SECURE=1`, постійне секретне сховище, централізований
rate limiting та захист від спаму. Не відкривай локальну конфігурацію напряму в інтернет.

Після розгортання збережи ту саму схему `/api` через reverse proxy, а SPA має
повертати `index.html` для `/owner` і `/invite/*`.

Сесії використовують стандартні [cookie FastAPI](https://fastapi.tiangolo.com/advanced/response-cookies/).
